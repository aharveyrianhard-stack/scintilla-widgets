Dollar Index and the US 10-Year: what we actually have

You were right to be sceptical. Both instruments exist in a feed we already pay for. The chart API cannot serve them, and that is a scope decision in our own code — not a gap in the market data.

Measured live 2026-09-22, 22:59–23:05 UTC · every cell below has the request and response behind it

The short answer. The dollar index and the 10-year yield are both available right now from FMP, with deeper history than anything else we hold — 55 years for the dollar, 64 years for the yield. Neither is available from Massive, and that is not fixable by guessing symbols.

Why the chart API says no. Our Massive plan is STOCKS_ADVANCED — shares and ETFs only. Indices, currencies and rates are not in the product at all. On top of that, the chart API only serves symbols already in its tracked list, and it rejects any symbol containing a colon, which is the character an index ticker needs.

The proof that this is our gate, not the provider's. UUP — an ordinary, heavily traded dollar ETF, same asset class as the IEF and TLT the chart API serves happily — also came back SYMBOL_NOT_TRACKED. A real ETF being refused proves the refusal means “not on our list”, never “does not exist”. Any future claim of “we don't have it” based on this endpoint alone is unsafe.

One trap worth naming

USDX looks like a dollar index ticker and is not one. On FMP it resolves to USDX = SGI Enhanced Core ETF, NASDAQ, 25.5681 — an unrelated bond fund. A search for DXY returns only DXYN (Dixie Group), DXYZ (Destiny Tech100), GDXY and JCDXY. Wiring either one in would have produced a chart that renders perfectly and shows the wrong instrument, which is worse than an empty panel.

Cheapest correct fix

Ranked. No new paid subscription is needed in any of these — FMP is already live in this estate and answered every request above.

1. Serve both from FMP Recommended

Add a narrow macro lane that reads DX-Y.NYB and ^TNX from FMP and hands them to the chart in the shape it already draws. Massive stays the authority for shares and ETFs; FMP covers the two things Massive's plan structurally cannot.

Cost
None. Proven working on the existing entitlement today.
What we get
Real values, 55 and 64 years of daily history, hourly OHLC for the dollar, and the full treasury curve as a side effect.
The honest catch
It is a second price lane, so provenance must be labelled per symbol — never let an FMP bar silently pass as a Massive one. The chart API's symbol filter also has to accept ^ and . for these, or they need internal aliases.

2. TradingView widget Same-day stopgap

Your instinct that this “can function for now” is right, and it is the fastest thing on this page to put on screen. But it is an iframe: the data never enters our stream, so it cannot feed the Geiger, cannot drive an indicator, and cannot be reliably held to the monochrome rule because its chrome is theirs.

Cost
None.
Use it for
A Hub page where you just need to see the line today.
Do not use it for
Anything the Station computes from. That breaks the build-from-the-live-stream rule.

3. ETF proxies already in our data Partial

TLT and IEF are tracked with 23 years of history, so a rates panel could ship this minute. It just would not be showing a yield. UUP would need adding to the corpus first, and once you are doing work anyway, option 1 gives the real instrument for the same effort.

Cost
None for TLT/IEF; corpus work for UUP.
The honest catch
A proxy that is labelled as a proxy is fine. A proxy labelled “10-Year” is a defect.

4. IBKR / IB Gateway Not recommended

You named this as a possible third feed, so it was checked properly rather than dismissed. /Users/alanharvey/SCINTILLA 0.5/ACTIVATE_IBKR_STREAM.command exists and its own header states the terms: IB Gateway must be open and logged in, with the API enabled on a socket port, and futures data needs CME/NYMEX/COMEX/ICE market-data subscriptions or you get delayed quotes.

Cost
No new software cost, but exchange subscriptions for the futures, and a standing cost in your hands.
Why it loses
It cannot run unattended — a logged-in desktop Gateway is exactly the “depends on Alan being there” shape that fails silently. It also writes into Supabase, which is explicitly not the source of truth for prices. It solves a problem FMP already solves for free.
When it would win
Only if you later want real futures order flow. Not for a dollar index or a cash yield.

What I did not do

Stated plainly so nothing here reads as more than it is.

  • I changed no chart code and shipped nothing to screen. This is a findings page only. The two chart twins were checked and are byte-identical at the production SHA (chart/index.html and station-shells/chart-v1/index.html, both md5 0b4a9750115464d0054be4a333e14c6f), and I left both untouched.
  • I did not add anything to the tracked corpus. Confirming UUP can be added is a reading of the gate's code, not a test of adding it.
  • I did not test the Massive provider's own API directly for index entitlement. The STOCKS_ADVANCED product line in the manifest and the four refusals are strong, consistent evidence, but a direct call with the provider key would be the last word. Treat “Massive structurally cannot serve DXY” as well-evidenced rather than proven at the provider boundary.
  • The chart API reported itself "ready": false with PROVIDER_FRAME_REFRESH_OUTSTANDING while I was testing. That did not affect these results — tracked symbols returned full 5,794-bar series throughout — but it is a separate live condition someone should look at.
  • I did not push or deploy. Branch and SHA are in the return note.
