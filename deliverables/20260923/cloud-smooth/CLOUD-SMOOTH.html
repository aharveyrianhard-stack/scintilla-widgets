Clouds, smooth as butter — 23 September 2026, before and after

The 13D/21D/50D/200D ribbon on every Station chart now draws as one clean curve, and the fill follows it. Not one number changed: the averages, the sessions they belong to, and the labels at the right edge are exactly what they were. Nothing here is deployed; it sits on branch station/cloud-smooth-20260923, built from production de95670.

“I'd like a proposal for smoothening the steppy behaviour… I don't want to do it mathematically. Just visually.” · “I want clean curves, smooth as butter.” · Ruling: “I don't need it to be really exact, the history of the curves. What matters is that the current level in the labels is exact.” — Alan, 22 Sep

1 · What changed on the pane, in one breath

  • The curve. One anchor per session, at that session's last bar. Between anchors a monotone curve (Fritsch–Carlson): it passes through every anchor exactly and can never pass beyond a real session value. The newest bar is always an anchor, so the curve ends exactly where the labels sit.
  • The fill follows the curve. The clouds are tiled along the curve about every two pixels with the same approved crossing-split geometry the Lab fixed on 21 Sep, so no hole and no overlap.
  • The labels are untouched. They still read the row's exact value and sit at exactly Y(value). Section 3 measures this on every captured pane.
  • The caption is the switch. Bottom-left of every pane: smoothed for the eye · labels exact · 400 daily bars · 60 warm-up not drawn. Click it and the ribbon is drawn stepped, one level per session, exactly as before; click again to smooth. ?steps=1 on a chart link does the same for a deep link. The lookback is now stated on the pane instead of hidden.
  • No white. Every near-white stroke and text on the chart surfaces is gone (section 5).

5 · No white: the audit of the chart surfaces

Every stroke, fill and text on chart/index.html and its byte-identical twin station-shells/chart-v1/index.html was searched for #C6C8DE, #F2F2F8, #fff and white-based rgba. Each use was replaced; the shared token declaration line stays (other pages read it) but nothing on the chart page uses --ink or --ink2 any more, and a test now fails if one comes back.

6 · How this was proven

  • Real Chromium (playwright-core 1.62.1, chromium 1234) on the MacBook, serving the production worktree at de95670 and the candidate worktree from the same static server the repository's browser proofs use. 1280×720 panes at 2× for the full shots, 3× for the corner zooms, 640×360 for the deck-size shots.
  • The provider was answered from real payloads captured once with read-only GETs (files written 2026-09-23T02:24:04Z; the provider's own derivation stamp on the candles is 2026-09-23T00:22:36.212Z): candles-TSLA-180.json (240 bars), candles-TSLA-D.json (400 bars), candles-SPY-180.json (240 bars), candles-SPY-D.json (400 bars), quotes-TSLA.json (1 quote), quotes-SPY.json (1 quote), universe.json (364 symbols). Supabase reads were answered from the repository's fixture universe; the canonical tickers set was answered from the same real 364-symbol universe, so the ownership handshake verified exactly as it does live. WebSockets were blocked. No page error on any capture.
  • Frame time (30 redraws averaged): the smooth drawing costs 1.81–3.62 ms per redraw against 0.42–1.23 ms before, at 1280×720. Hover and pan redraw the same way.
  • Tests: tests/station-clouds.test.mjs 29/29 (23 existing + 6 new: exact anchors and no overshoot, one anchor per session, sampled rows keep the ribbon's rules, smooth default with ?steps=1, labels untouched, no near-white). Whole suite 373 tests, 353 pass; the 20 failures are the same 20 that fail on production de95670 — none new, none fixed.
  • Pixel differences were measured with an image diff, caption box masked: 3h 0.783% / 1.089%, 1D 0.021% / 0.019%, 1D zoomed 0.063% / 0.088%.

7 · What this does not claim

  • Nothing is deployed or pushed. The live Station still draws the stepped ribbon until root deploys this branch.
  • The deck's own text colours and the other pages' token declarations were not changed (section 5 lists them).
  • The provider payloads are a snapshot from the capture time; the labels above are exact for that snapshot, not a live quote.
  • The proposals page keeps its four variants; variant c is marked as the Station default and ?steps=1 marks a. Its mode buttons remain labels, as before.
