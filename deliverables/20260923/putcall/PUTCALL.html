Put / call

Cboe counts every put and every call traded on its exchanges and publishes the ratio after the close, one number per session. That is the number here, from 2 November 2006 to 22 September 2026, drawn as a Scintilla chart on the Station and read by the sentiment gauge.

It is yesterday’s number, and it always will be. Cboe has no live put/call feed — the file for a session appears after that session closes — so every screen that shows it says which session it belongs to. Nothing here pretends otherwise, and nothing holds one daily number flat across an intraday chart to make it look live.

The note that Cboe retired the free daily files in October 2019 was half right, and the wrong half. The CSV files retired. The data did not: a free JSON file is published for every session at cdn.cboe.com/…/<date>_daily_options, and reading it back is where everything after 2019 in these charts came from. The file also carries the raw call and put volumes, so the printed ratio can be checked against them — on 22 September 2026 the equity line printed 0.47 and its own volumes give 1,145,629 ÷ 2,460,777 = 0.466.

On the Station

The PCC pane used to show TradingView’s free widget, because the Station held no series of its own. It now draws the Scintilla chart with the cloud ribbon, like every other pane, and the readout names the session.

The same pane opened up, with the ribbon and the session dates along the bottom:

The line is in the neutral grey, not the green or red every other pane uses. Green on this wall means the line went up, and on a price that also reads as good news. On a put/call ratio “up” is more puts than calls — fear to one reader, a contrarian buy to the next — so this pane claims no direction and lets the number speak.

TICK, CUMTICK, TRIN and ADD are untouched and still show TradingView’s chart under its name.

In the sentiment gauge

CNN’s fear and greed index has seven market inputs and we held five. Put/call was one of the two missing ones, refused with that Oct-2019 note. It now reads this same series — the five-day average, like CNN’s, and inverted, because more puts than calls is fear — so the gauge counts six of seven. Only 52-week highs against lows is still missing, and it still says so on its own row.

What would run, how often, and how to stop it

Nothing is on a timer today. No schedule was created, nothing was deployed, and no machine was started. What exists is the collector and the route that calls it.

ONE run a day, after the close:
  POST/GET  ${BAR_SERVICE}/refresh-putcall          all four series
  GET       ${BAR_SERVICE}/acquire-putcall?symbol=PCC   one series, what the chart API asks by itself

WHEN     21:15 ET, every trading day. Cboe’s file for a session appears after that session
         closes; the serving rule does not expect it before 21:00 ET, so a run at 21:15 is late
         enough to find it and early enough to be hours before anyone looks in the morning.

HOW IT BEHAVES  one request per second, never two at once. A 429 or a 5xx stops the run on the
         spot. A single 403 is Cboe saying “no file for that date” and is recorded as a gap;
         three in a row is Cboe saying stop, and the run stops. Every stop names the date it
         stopped on, and the next run resumes from there.

HOW TO STOP IT  it is a Fly machine schedule on scintilla-massive-stocks-batch, so:
         fly machine stop <id> -a scintilla-massive-stocks-batch     stop the next run
         fly machine update <id> --schedule ''                        remove the schedule
         Deleting nothing else: the stored series stays exactly as it was, and the chart API
         keeps serving it until it falls behind, at which point it refuses it by name rather
         than showing it as current.

What is honest about this, and what is not finished

  • The seam is real, and the two sources never overlap. Everything to 4 October 2019 is the old Supabase table; everything from 7 October 2019 is Cboe’s file. They abut exactly — I asked Cboe for 4 October and got a 403, so its archive begins the next session. That means there is no shared day to cross-check one source against the other, and none was invented to make the join look smoother than it is.
  • PCSPX has no deep history. The old table held total, index and equity only, so the S&P 500 line starts in October 2019 rather than 2006. It is not padded to look longer.
  • 49 of the 0 sessions asked for had no file. Almost all are exchange holidays the calendar in this code does not list before 2025, so the run asked and Cboe answered “no file”. No value was invented for them and no gap was filled in.
  • Nothing is deployed. These are branches for review. The series will not appear on the live Station or in the live gauge until the coordinator merges and deploys them.
  • The intraday widths are the daily points. Ask for PCC at five minutes and the API answers with the daily sessions and says so, rather than refusing the timeframe or inventing a shape.
