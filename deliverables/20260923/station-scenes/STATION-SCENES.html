The workbench, ready for tomorrow's versions

You said new copies of the oscillator workbench are coming tonight or tomorrow. So a workbench is now a type of page, not a one-off: it is a list of charts, each with a symbol, a named study stack, and optionally its own timeframe. Adding tomorrow's version is adding an entry to a list — no new code.

The stacks that exist tonight, all built from the Station's own cloud ribbon:

  • PRICE — price only, ribbon off.
  • CLOUDS — the 13D/21D EMA and 50D/200D SMA ribbon.
  • OSCILLATOR — that ribbon plus the 8-day EMA and the 100-day SMA. This is what MU and QQQ carry on the workbench page.
  • STEPPED — the ribbon drawn stepped rather than smoothed.

Each chart writes its stack into its own address, so a workbench slot can never quietly inherit the wall's cloud switch and become a different study than the page says it is. A slot with its own timeframe overrides the one timeframe bar for that slot only; without one, it follows the wall like everything else.

When you send the new layouts, the honest limit is this: the Station can only draw the indicators it owns. If your new workbench uses TradingView studies we do not compute, I can name them on the page and keep the TradingView button beside each chart, but I cannot draw them from our data until they exist here.

Getting to PCC in one move

  • ← and → move one page. They are ignored while you are typing in a ticker box or a menu, so entering a symbol never changes the page under you.
  • Edge arrows sit at the far left and far right of the wall, in the same two places on every page, at every width.
  • pages opens the list: type a page name (MACRO, blue) or a ticker (PCC, XLB) and press Enter for the first match, or click. Escape closes it.
  • The rail buttons themselves are still one click each, and the scene menu still names the page.

Where each number comes from

  • Every price, candle and percentage on these pages comes from the chart API at scintilla-massive-chart-api.fly.dev — the same source the Station always used. I wrote nothing to any price table and ran no acquisition.
  • VIX, US10Y, oil, gold and bitcoin come through that API from FMP; PCC comes through it from Cboe, one print per session after the close. Equities come from the Massive provider's own bars.
  • For the screenshots I served the branch from this MacBook and re-sent each chart-API request from the command line carrying the scintillahub.ai origin the API requires, because a local page is not that origin. Those were the ordinary public reads the deployed Station makes; nothing was written.

IGV and NVTS

These two are the only symbols in your twelve layouts the chart API does not carry. Asked directly, it answers SYMBOL_NOT_TRACKED — "symbol not in the tracked universe". Its universe is 364 names.

I left both in their pages on purpose, so the page is your page: the slot says NOT SERVED BY CHART API instead of vanishing, and it will simply start drawing the day the universe carries it.

What it takes, in order — I wrote step 1 and stopped, because the rest are production writes this lane is not allowed to make:

  1. Two rows in the provider's instrument_map table. Written as a migration with its rollback: universe/2026-09-23_add_igv_nvts.sql.
  2. An acquisition manifest for each symbol in R2 — this is what the bar service actually checks for membership, so the table row alone changes nothing — then a tail pass to fetch their history.
  3. The universe count and its fingerprint then change from 364 / ab8f7965…, and three places pin those and must move with them: two constants in the Station's own provider file and the chart API's settled-universe settings.

So adding a name is additive in the database and not additive downstream. That is why I did not half-do it.

What could be wrong

  • Your INDEXES layout has six charts and five distinct names — TradingView shows one of them twice. I did not guess which, so the page carries the five names and leaves the sixth slot empty and editable. Tell me which one repeats and it is a one-line change.
  • Each page declares a timeframe (yours are mostly daily), but the Station has one timeframe bar that drives the whole wall, and I did not change that. So a page opens at whatever timeframe the wall is on, not at the layout's own. Say the word and pages can set the wall's timeframe when you enter them.
  • Auto-rotate still cycles the original nine screens only, not your twenty pages. That was a judgement call: rotation is a slideshow you set up, and I did not want it wandering into a workbench.
  • The workbench stacks are my reading of "oscillator" — the cloud ribbon plus its two extra levels. Your actual TradingView stack (RSI, MACD, Williams %R) is not what the Station draws in a pane today.
  • Nothing here has been seen on the real domain. Everything above is this branch served locally in a real browser. It has not been deployed.
